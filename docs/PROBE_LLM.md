## Setup

- Provider: Nebius Token Factory, OpenAI-compatible `chat/completions`.
- Sampling: temperature 0.6, top_p 0.95, max_tokens 2500. There is no seed parameter, so repeated samples differ only by server-side sampling.
- Prompt: a short task description, a 10-parameter table, three prior results, and a request for 2 designs (one mutation, one exploratory) after a short analysis.
- Modes: `tool` = forced tool call (`tool_choice` names `submit_designs`); `json_schema` = `response_format` with `strict: true`. Both use the same JSON schema, with min/max on every numeric field and enums for the categorical ones. `tool+no_think` = `tool` plus `chat_template_kwargs: {enable_thinking: false}`.
- 2 calls per model and mode, run one at a time. Cost is estimated from returned usage and catalogue prices.

## Observations

- No HTTP errors: every model accepted a forced `tool_choice` naming the function, a strict `response_format` json_schema, and `chat_template_kwargs`. Accepted is not the same as enforced; see below.
- `NVIDIA-Nemotron-3-Nano-30B-A3B` tool: 2/2 calls hit max_tokens=2500 (finish_reason `length`) before the answer was complete.
- `Nemotron-3_5-Lightning` json_schema: 2/2 answers began with free-form text instead of JSON, so the strict schema was not enforced by the decoder for this model; its reasoning arrived inline in `content`, not in a separate field.
- `Nemotron-3_5-Lightning` json_schema: 2/2 calls hit max_tokens=2500 (finish_reason `length`) before the answer was complete.
- With thinking on, reasoning arrived outside `content` in `reasoning` (`NVIDIA-Nemotron-3-Nano-30B-A3B`) and `reasoning_content` (`Nemotron-3_5-Lightning`, `nemotron-3-super-120b-a12b`, `Nemotron-3-Ultra-550b-a55b`). The client reads either field, keeps the text in the cache and never parses it.
- `chat_template_kwargs: {enable_thinking: false}` (tool mode, thinking on -> off): `NVIDIA-Nemotron-3-Nano-30B-A3B` 2500 -> 380 completion tokens, p50 43.5 -> 12.8 s, clean 0/2 -> 2/2; `Nemotron-3_5-Lightning` 1306 -> 420 completion tokens, p50 5.0 -> 2.0 s, clean 2/2 -> 2/2; `nemotron-3-super-120b-a12b` 442 -> 301 completion tokens, p50 2.9 -> 2.0 s, clean 2/2 -> 2/2; `Nemotron-3-Ultra-550b-a55b` 1819 -> 410 completion tokens, p50 5.8 -> 2.0 s, clean 2/2 -> 2/2. No separate reasoning came back with thinking off.
- Same messages, different billing: tool mode averaged 1330 prompt tokens and json_schema 600. The tool definition is rendered into the prompt; the `response_format` schema is not.
- No parsed response broke a bound, an enum or a cross-field rule in any mode. The probe cannot tell decoder enforcement of min/max apart from plain compliance, so the validators remain mandatory.

## Recommendation

**Proposer: `nvidia/nemotron-3-super-120b-a12b` with `tool` mode, thinking on.** In this probe it was 2/2 clean, p50 latency 2.9 s, about $0.0008 per call, with at most 469 completion tokens.

The other mode on the same model (`json_schema`) was 2/2 clean at $0.0011 per call and p50 5.5 s.

Ultra in the same mode was 2/2 clean at 8.4x the cost per call; it is not needed for format reliability.

For latency-sensitive calls (the live-bout Director), `tool+no_think` on the same model was 2/2 clean at p50 2.0 s.

Reasoning tokens count toward `max_tokens`, so production calls should leave generous headroom above the largest completion seen here; 2500 was the probe cap. Validators still run on every design (bounds, cross-field rules, geometry) with at most one repair call.
